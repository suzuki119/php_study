# NUTS SHOP 概要

素焼きナッツ・ミックスナッツなどを扱う小規模ECサイトという想定で作っている。
「実店舗を持たない小さな乾物屋が、まず最小限の機能でネット販売を始めてみる」というストーリーで機能を積み上げてきた。以下、機能ごとに「なぜ付けたか」「なぜそのデザインにしたか」を記録する。

## 1. 商品閲覧・検索（product.php / detail.php）

- **なぜ付けたか**：ECサイトの入口として、まず「何が売っているか一覧できて、名前で探せる」ことが最低条件だと考えた。ナッツは種類が増えると似た商品名が並ぶため、キーワード検索（`LIKE`検索）を早い段階で用意した。
- **なぜそのデザインか**：一覧はテーブルではなくカードグリッド（`.product-grid` / `.card`）にした。写真映えが購買意欲に直結する食品ジャンルなので、画像を主役にしたカードUIの方が、行ベースの表よりも「お店の棚を眺める」感覚に近いと判断した。画像が用意できていない商品でも壊れて見えないよう、`onerror`でサムネイルを非表示にし、代わりに🥜のプレースホルダーを背景に敷いている。
- 商品詳細では価格をそのまま出さず、`tax_ratio`テーブルの税率・セール率を反映した実売価格を都度計算して表示している。将来的にセールを頻繁に行う想定のため、価格を商品テーブルに直接持たせず「税・セール設定」から動的に算出する方式にした。

## 2. カート・購入（cart.php / purchase-input.php / purchase-output.php）

- **なぜ付けたか**：会員登録前に「とりあえず買い物カゴに入れて検討したい」という行動を想定し、カートはログイン不要（セッションのみ）で使えるようにした。一方、購入確定はログインを必須にしている。これは、購入履歴やポイントを個人に紐づける必要があるための最低限の制約。
- **個数指定にスライダー＋テキストボックスの両方を用意**：ナッツは1〜2個ではなく「まとめ買い」される想定（ギフト用の複数個購入など）なので、スライダーで大まかに、テキストボックスで正確に、と両方から個数調整できるようにした（`footer.php`のJSで相互同期）。
- **購入確定でポイントを付与**：リピート購入を促す仕組みとして、購入総額に応じたポイント（`tax_ratio.point_ratio`）を都度計算して顧客に加算する設計にした。ポイント比率を商品側ではなく「店舗設定」側に持たせているのは、キャンペーンで比率を変えたい場面を想定したため。

## 3. お気に入り（favorite.php 系）

- **なぜ付けたか**：ナッツのようなリピート消費財は「今すぐ買わないが定期的に気になる商品」が多いと想定し、カートとは別に長期保存できるお気に入りリストを設けた。カートは「今回の買い物」、お気に入りは「継続的なウォッチリスト」という役割分担にしている。

## 4. レビュー（review-input.php / review-output.php / review.delete.php）

- **なぜ付けたか**：ナッツは味・食感の好みが分かれる商品なので、購入前に他の人の評価が見られると安心感につながると考え、5段階評価＋自由記述のレビュー機能を追加した。商品一覧・詳細ページの両方にレビュー件数と平均評価を出し、「レビューがまだ無い商品」も明示することで、購入者の判断材料を増やしている。
- **削除は投稿者本人のみ**：レビューは公開情報として残す一方、荒らしや誤投稿の訂正ができるよう、`customer_id`とセッションを突き合わせて本人にだけ削除リンクを表示する設計にした。

## 5. 会員機能（login / customer-input / customer-delete）

- **なぜ付けたか**：購入履歴・ポイント・レビューの本人紐付けのために最低限の会員登録・ログイン・退会を用意した。決済代行やメール認証などは対象外とし、あくまで学習用ショップとして「顧客IDに紐づく機能を成立させるための土台」という位置づけ。

## 6. 税率・セール・ポイント比率の管理（tax-update-input.php / tax-update-output.php）

- **なぜ付けたか**：価格をハードコードすると季節セールや税率改定のたびにDBの商品データを全件書き換える必要が出るため、店舗全体に効く「税率・セール率・ポイント比率」を1箇所（`tax_ratio`テーブル）で管理できるようにした。これにより「本日だけ全品10%オフ」のような運用が、商品データを一切触らずに実現できる。

## 7. 商品編集（owner/edit3.php）＋商品画像アップロード

- **なぜ付けたか**：ナッツの仕入れ・入れ替えは頻繁に起こる想定のため、商品の追加・更新・削除をSQLを直接叩かずに済むよう、1画面（`edit3.php`）で完結する管理フォームを用意した。
- **画像アップロード機能**：それまで商品画像は`user/image/{商品ID}.jpg`にファイルを手動で置く運用だったが、これは店舗運営者にとって現実的でない（サーバーにFTPで入れる前提になってしまう）。そこで編集フォームにファイル選択欄を追加し、アップロードされた画像を検証（`getimagesize`で画像ファイルであることを確認）した上で商品IDに対応する`.jpg`として保存するようにした。ファイル名を商品IDで固定しているのは、一覧・詳細ページ側の画像参照ロジックを変更せずに済ませるため。

## 8. デザイン全体の方針（style.css）

- **配色**：白ベースに焙煎ナッツを思わせるブラウン系（`--accent: #8b5e34`など）を基調にし、素朴で温かみのある「乾物屋」らしい印象を狙った。
- **ヘッダーはガラス風の浮遊ピル型**（`backdrop-filter`＋角丸）にし、スクロールしても常に導線（商品・カート・購入など）にアクセスできるようにした。ページ数が多いショップなので、常時ナビゲーションを優先した。
- **ボタン・リンクはピル型で統一**し、テーブル内リンクだけは装飾を抑える（`td a`）ことで、「操作ボタン」と「一覧内の軽いリンク」を視覚的に区別している。
- **レスポンシブ対応**：スマホでの買い物利用を想定し、640px以下でカードグリッドの列数を詰め、テーブルは横スクロール可能にしている。

## 今後の検討事項

- **セットメニュー機能（検討中）**：「ナッツの詰め合わせセット」のように、1つの販売単位に複数商品を紐づけたいという要望から、`sets`（セット情報）と`setmenu`（セットと商品の中間テーブル）の2テーブル構成を検討中。単品売り中心だった設計に、まとめ買い・ギフト需要向けの販売単位を追加する狙い。
