# NUTS SHOP

## 概要

「NUTS SHOP」は、素焼きナッツ・ミックスナッツなどを扱う小規模ECサイトを想定して作ったWebアプリです。フレームワークを使わず、素のPHP・PDO・生SQLで「商品閲覧→カート→購入→レビュー→会員管理→店舗運営」までを一通り実装しました。

「実店舗を持たない小さな乾物屋が、まず最小限の機能でネット販売を始めてみる」というストーリーを設定し、必要になった機能を一つずつ積み上げていく形で開発しました。

## 制作の背景と目的

このプロジェクトの目的は、**フレームワークに頼らずPHP＋MySQLでECサイトの基本機能を一通り自力で組み上げること**でした。

セッションによる認証・カート管理、PDOを使ったSQL操作、購入処理まわりのデータ整合性、管理者権限による画面の出し分けなど、ECサイトに最低限必要な要素を、ライブラリの助けを借りずに設計・実装することで、PHPの基礎体力を鍛える狙いがありました。

## コンセプト

コンセプトは「**乾物屋の実店舗をそのままWebに移したような、素朴で温かみのある買い物体験**」です。

派手な演出は避け、白ベースに焙煎ナッツを思わせるブラウン系の配色でまとめ、カードグリッドで「お店の棚を眺める」感覚を再現しました。機能面でも、実店舗の乾物屋がそのままオーナーになったときに運用できる範囲（SQLを直接触らずに商品・セットを編集できる管理画面など）を意識しています。

## 機能紹介

| 機能 | 内容 |
| --- | --- |
| 商品閲覧・検索 | 商品をカードグリッドで一覧表示し、名前でのキーワード検索（`LIKE`検索）ができる |
| 商品詳細 | 税率・セール率を反映した実売価格を動的に算出して表示。レビュー件数・平均評価も表示 |
| カート | ログイン不要（セッションのみ）で追加・数量変更が可能。個数はスライダーとテキストボックスの両方で調整できる |
| 購入 | ログインユーザーのみ購入確定可能。購入総額に応じたポイントを自動付与 |
| お気に入り | カートとは別に、長期的なウォッチリストとして商品を保存できる |
| レビュー | 5段階評価＋自由記述。削除は投稿者本人のみ可能 |
| 会員機能 | 会員登録・ログイン・退会。購入履歴・ポイント・レビューを顧客IDに紐づける |
| 税率・セール・ポイント比率管理 | 店舗全体の税率／セール率／ポイント比率を1箇所（`tax_ratio`テーブル）で管理 |
| 商品編集（オーナー専用） | 商品の追加・更新・削除、商品画像のアップロードをフォーム上で完結 |
| セット編集（オーナー専用） | 複数商品をまとめた「セット商品」を作成・編集。対象商品にチェックを入れると本来価格を自動集計 |

## デザイン・実装

### カードグリッドでの商品一覧

商品一覧はテーブルではなくカードグリッド（`.product-grid` / `.card`）で表示しています。写真映えが購買意欲に直結する食品ジャンルなので、画像を主役にしたカードUIの方が行ベースの表よりも「お店の棚を眺める」感覚に近いと判断しました。画像が未登録の商品でも壊れて見えないよう、`onerror`でサムネイルを非表示にし、代わりに🥜のプレースホルダーを背景に敷いています。

### 税・セール・ポイントを「店舗設定」に切り出す設計

価格を商品テーブルに直接持たせず、`tax_ratio`テーブルの税率・セール率をもとに実売価格をその都度計算する方式にしました。これにより「本日だけ全品10%オフ」のようなキャンペーンが、商品データを一切触らずに実現できます。同様に、購入時に付与するポイントの比率も商品側ではなく店舗設定側に持たせ、キャンペーンで比率を変えたい場面に対応できるようにしています。

### カートは非ログイン、購入確定はログイン必須

会員登録前でも「とりあえずカゴに入れて検討したい」という行動を想定し、カートはセッションのみで使えるようにしました。一方、購入確定はログインを必須にしています。これは、購入履歴やポイントを個人に紐づける必要があるための最低限の制約です。個数指定にはスライダーとテキストボックスの両方を用意し、`footer.php`のJavaScriptで値を相互同期させています。まとめ買い（ギフト用の複数個購入など）を想定した調整です。

### レビューの本人限定削除

レビューは公開情報として残しつつ、荒らしや誤投稿の訂正ができるよう、`customer_id`とセッションを突き合わせて投稿者本人にだけ削除リンクを表示する設計にしました。

### 商品画像アップロード

当初、商品画像は`user/image/{商品ID}.jpg`にファイルを手動で置く運用でしたが、これは店舗運営者にとって現実的ではありません（サーバーにFTPで入れる前提になってしまう）。そこで編集フォームにファイル選択欄を追加し、アップロードされた画像を`getimagesize`で検証したうえで商品IDに対応する`.jpg`として保存するようにしました。ファイル名を商品IDで固定しているのは、一覧・詳細ページ側の画像参照ロジックを変更せずに済ませるためです。

### セット商品機能

「ナッツの詰め合わせセット」のように、1つの販売単位に複数商品を紐づけたいという要望から、`sets`（セット情報）と`setmenu`（セットと商品の中間テーブル）の2テーブル構成を追加しました。オーナー画面では対象商品にチェックを入れると、JavaScriptがリアルタイムで本来価格（単品合計）を集計して表示し、セット価格をいくらに設定すればお得感を出せるかを運営者が判断しやすくしています。

### 管理者専用のアクセス制御

オーナー向けの編集画面には`require-owner.php`を共通で挟み、セッションに管理者フラグが立っていないユーザーには「このページは管理者のみアクセスできます」と表示して処理を止めるようにしています。認証まわりの共通処理を1ファイルに切り出すことで、新しい管理画面を追加する際もincludeするだけで済むようにしました。

### デザイン全体の方針

- **配色**：白ベースに焙煎ナッツを思わせるブラウン系（`--accent: #8b5e34`など）を基調にし、素朴で温かみのある「乾物屋」らしい印象を狙いました。
- **ヘッダーはガラス風の浮遊ピル型**（`backdrop-filter`＋角丸）にし、スクロールしても常に導線（商品・カート・購入など）にアクセスできるようにしました。ページ数が多いショップなので、常時ナビゲーションを優先しています。
- **ボタン・リンクはピル型で統一**し、テーブル内リンクだけは装飾を抑えることで、「操作ボタン」と「一覧内の軽いリンク」を視覚的に区別しています。
- **レスポンシブ対応**：スマホでの買い物利用を想定し、640px以下でカードグリッドの列数を詰め、テーブルは横スクロール可能にしています。

## 振り返り

- フレームワークなしでカート・購入・ポイント付与までを実装したことで、セッション管理やSQLのトランザクション的な整合性（在庫・ポイント・購入履歴の更新をどの順序で行うか）を意識する力がつきました。
- 「価格を商品テーブルに固定で持たせず、税率・セール率から動的に算出する」という設計判断は、後からセット商品機能を追加する際にも活きました。データを一箇所に集約しておくことの効果を実感できました。
- 管理画面（商品編集・セット編集・画像アップロード）を後追いで実装していく中で、運営者視点での使いやすさ（SQLを直接触らせない、FTP不要にする）を都度考える経験ができたのは大きな学びでした。
